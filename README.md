# مساعد النورس الذكي | NAWRAS AI AGENT

واجهة عربية من اليمين إلى اليسار لمساعد عمليات موجّه لسياق الشحن والتوصيل. يدعم الإصدار الحالي الدخول بالبريد وكلمة المرور عبر Supabase Auth، ويتيح المحادثة مع Gemini للتحليل والتخطيط، وGroq للردود السريعة عند إعداد مفتاحه، وOpenRouter لتجربة النماذج المتاحة مباشرةً من قائمته الحية. لا ينفّذ التطبيق تغييرات على نظام النورس أو قاعدة البيانات.

## التشغيل المحلي

يتطلب Node.js 20 أو أحدث ومشروع Supabase.

```bash
npm install
cp .env.example .env.local
npm run dev
```

تحتاج الواجهة إلى `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في `.env.local`. استخدم المفتاح العام (publishable/anon) فقط. لا تضع أي مفتاح مزود ذكاء اصطناعي أو `service_role` في متغيرات `VITE_` أو في ملفات المتصفح.

## النشر على GitHub Pages

يُنشر الموقع تلقائياً عند الدفع إلى الفرع `main` عبر `.github/workflows/deploy-pages.yml`. رابط الإنتاج: `https://aahhhjk99-pixel.github.io/NAWRAS-AI-AGENT/`. يحتوي Workflow على رابط Supabase ومفتاح عام مخصص للاستخدام في المتصفح فقط.

## Supabase Auth وEdge Function

- أنشئ الحسابات المعتمدة من لوحة Supabase ضمن Authentication → Users. واجهة الموقع مخصصة لتسجيل الدخول، ولا تعرض تسجيل حساب عام.
- تتطلب `ai-chat` JWT صالحاً، ثم تتحقق أيضاً من البريد مقابل السر الخادمي `AI_ALLOWED_EMAILS`.
- يقتصر CORS على الأصول المحددة في `ALLOWED_ORIGINS`؛ قيمة النشر الحالية هي أصل GitHub Pages فقط، دون مسار المشروع.
- مفاتيح Gemini وGroq وOpenRouter تُحفظ كأسرار Edge Functions على الخادم فقط.
- لا تضع أسرار المزودات في GitHub Actions أو المستودع، ولا تطبعها في الطرفية.
- اضبط `AI_DEFAULT_PROVIDER=gemini` اختيارياً، ويمكن تخصيص النماذج عبر `GEMINI_MODEL` و`GROQ_MODEL`.

الأسرار اللازمة في بيئة Supabase عند تفعيل كل مزود:

```text
ALLOWED_ORIGINS=https://aahhhjk99-pixel.github.io
AI_ALLOWED_EMAILS=<comma-separated authorized account emails>
AI_DEFAULT_PROVIDER=gemini
GEMINI_API_KEY=<server-side key>
OPENROUTER_API_KEY=<server-side key>
GROQ_API_KEY=<server-side key, optional until Groq is enabled>
```

يدعم Gemini افتراضياً `gemini-flash-latest`، وGroq `llama-3.1-8b-instant`. يستدعي التطبيق قائمة نماذج OpenRouter عبر الدالة الخادمية ويحصر استخدام النموذج المختار في القائمة التي يعيدها المزود. اختيار مزود مختلف لا يقوم بتحويل الطلب تلقائياً إلى مزود آخر، لتجنب استخدامه أو احتسابه دون اختيار المستخدم.

انشر الدالة `ai-chat` مع `verify_jwt=true`. لا تتطلب هذه النسخة ترحيلات أو تغييرات في قاعدة البيانات.

## حدود مهمة

- تكامل نظام النورس مقصور على حالة تعريفية/معاينة. لا توجد قراءة أو كتابة أو أوامر دخول آلي على نظام الشركة.
- المحادثات غير محفوظة في قاعدة البيانات. مراجعة سياسة الاحتفاظ ومشاركة البيانات مع مزود الذكاء الاصطناعي لازمة قبل الاستخدام الفعلي.
- حد الرسائل في الدالة 20 رسالة لكل طلب، وحتى 4,000 محرف للرسالة و24,000 محرف إجمالاً.
- لا تتضمن النسخة سقفاً مالياً أو تحديد معدل استخدام على مستوى المستخدم. حماية قائمة البريد تقلل الوصول لكنها لا تُغني عن إضافة حدود استخدام ومراقبة قبل فتحها لمجموعة أوسع.
- لا توجد إدارة أدوار للموظفين؛ وصول الدالة محصور بالعناوين المدرجة في `AI_ALLOWED_EMAILS`.
- ألوان الواجهة مستوحاة من الشعار والصور العامة المنشورة، وليست دليلاً رسمياً كاملاً للعلامة. راجع `docs/BRAND_GUIDE.md`.

## قواعد أمان أساسية

- المفتاح العام Supabase وحده مسموح في المتصفح؛ لا تستخدم `service_role` في العميل.
- مفاتيح مزودي الذكاء الاصطناعي تبقى في أسرار Edge Functions.
- لا ترسل كلمات مرور أو رموز جلسات أو مفاتيح سرية إلى المساعد.
- لا تنفّذ عمليات مالية أو حساسة أو حذفاً قبل توثيق الصلاحيات وموافقة بشرية وفحص مستقل للنتيجة.
