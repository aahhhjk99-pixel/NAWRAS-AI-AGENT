# أساسيات الأمان

## أسرار الاعتماد

- `VITE_SUPABASE_ANON_KEY` مفتاح عام مخصص للمتصفح، وتبقى صلاحيات البيانات محكومة بـ RLS.
- مفاتيح OpenAI وGemini وAnthropic تحفظ في Supabase Edge Function Secrets فقط.
- يمنع تضمين `service_role` أو رموز الجلسات في الواجهة أو ملفات Git.

## الطلبات

- تتطلب الدالة جلسة مستخدم صالحة عبر إعداد التحقق الافتراضي لـ Supabase Functions.
- يضبط `ALLOWED_ORIGINS` بقائمة الأصول المسموح بها، مفصولة بفواصل.
- يفرض الخادم حدوداً على عدد الرسائل وحجم كل رسالة.
- لا يقبل العميل عنوان مزود أو مفتاحه؛ اختيار المزود يتم من إعدادات الخادم.

## ما يلزم قبل الإنتاج

تسجيل الدخول وإدارة الأدوار، وحدود المعدل والتكلفة، وسياسة احتفاظ واضحة للمحادثات، ومراقبة منقحة من البيانات الحساسة، واختبار RLS، ومراجعة مستقلة لتدفق البيانات مع مزودي الذكاء الاصطناعي. لا تفعّل أي إجراء خارجي أو مالي قبل موافقة الشركة والتحقق من صلاحياته ونتيجته.
