# قائمة التحقق اليدوية — NAWRAS AI AGENT

## الواجهة والدخول
- [ ] `npm run typecheck` و`npm test` و`npm run build` تنجح.
- [ ] تفتح الواجهة بالعربية وRTL على الهاتف والحاسوب.
- [ ] المستخدم غير المسجل يرى شاشة الدخول فقط؛ لا يستطيع استخدام المحادثة قبل تسجيل الدخول.
- [ ] تسجيل الدخول والخروج يعملان عبر Supabase Auth وتظهر جلسة المستخدم النشطة.
- [ ] لا تعرض الواجهة حالة اتصال ناجح دون فحص.

## مزودات الذكاء الاصطناعي
- [ ] Gemini ظاهر بوصفه خيار التحليل والتخطيط.
- [ ] Groq معطّل عند غياب `GROQ_API_KEY`، ويصبح متاحاً عند إضافة مفتاح صالح إلى أسرار الخادم.
- [ ] OpenRouter يجلب قائمة النماذج من Edge Function، ولا يرسل المفتاح إلى المتصفح.
- [ ] لا يقبل الخادم نموذج OpenRouter خارج القائمة الحالية.
- [ ] لا يجري تحويل تلقائي إلى مزود آخر عند فشل المزود الذي اختاره المستخدم.
- [ ] تظهر حالات التحميل والأخطاء بوضوح، ولا يمكن إرسال رسالة فارغة أو أثناء التحميل.

## Supabase والأسرار
- [ ] يحتوي `.env.local` على رابط Supabase ومفتاح anon/publishable العام فقط.
- [ ] لا يوجد مفتاح `service_role` أو مفتاح مزود ذكاء اصطناعي في حزمة المتصفح أو Git.
- [ ] `ai-chat` يتطلب JWT صالحاً ويفحص البريد مقابل `AI_ALLOWED_EMAILS`.
- [ ] يقتصر CORS على الأصول المحددة في `ALLOWED_ORIGINS`.
- [ ] ترفض الدالة المدخلات الطويلة أو الرسائل غير الصالحة.
- [ ] تظل `verify_jwt = true` في إعداد Supabase.
- [ ] تضاف حدود معدل الاستخدام والميزانية قبل فتح الخدمة لمجموعة أوسع أو استخدامها إنتاجياً.

## تكامل النورس
- [ ] لا يجري أي استكشاف أو اتصال إلا بتفويض الشركة.
- [ ] لا تنفذ النسخة الحالية عمليات تغيير في نظام النورس.
- [ ] توثّق كل قدرة مستقبلية مع مصدرها وحالة التحقق.
- [ ] تتطلب العمليات الحساسة موافقة بشرية وتحققاً مستقلاً.
